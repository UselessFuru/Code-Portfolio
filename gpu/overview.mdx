This collection of CUDA programs was written by **Alexander Dela Cruz** (and co-authored with **Jose Espino** for Assignment 3) as coursework in GPU parallel computing. Starting from first principles — allocating device memory, launching a kernel, copying results back — the work progressively introduces more sophisticated scheduling strategies, signal-processing algorithms, and high-performance simulation techniques. All code was compiled and executed on the **TACC Lonestar6 HPC cluster** using **CUDA 11.3** and submitted through the **SLURM** job scheduler.

## Key CUDA Concepts Demonstrated

<AccordionGroup>
  <Accordion title="Global Thread Indexing">
    When a kernel spans multiple blocks, each thread needs a unique position in the
    overall data array. The standard formula used throughout these programs is:

    ```cuda
    int globalThreadIdx = blockIdx.x * blockDim.x + threadIdx.x;
    ```

    This maps every thread across all blocks to a unique array index, enabling true
    data-parallel execution with no overlap.
  </Accordion>

  <Accordion title="CUDA Memory Model">
    The fundamental host ↔ device workflow appears in every assignment:

    1. **`cudaMalloc`** — allocate memory on the GPU
    2. **`cudaMemcpy` (HostToDevice)** — send input data to the GPU
    3. **Kernel launch** (`<<<gridDim, blockDim>>>`) — execute in parallel
    4. **`cudaMemcpy` (DeviceToHost)** — retrieve results back to the CPU
    5. **`cudaFree`** — release GPU memory

    The GPU cannot read host (CPU) memory directly; all data must be explicitly transferred.
  </Accordion>

  <Accordion title="Shared Memory Tiling">
    The N-body project's GPU kernel uses `__shared__` memory as a fast, on-chip scratchpad.
    By loading tiles of particle positions into shared memory before computing forces,
    the kernel reduces global memory traffic by a factor equal to the tile size (1,024),
    dramatically improving throughput.
  </Accordion>

  <Accordion title="cudaEvent Timing">
    The N-body GPU project uses CUDA events for precise kernel-only timing — excluding
    host-device transfer overhead:

    ```cuda
    cudaEvent_t start, stop;
    cudaEventCreate(&start);
    cudaEventCreate(&stop);
    cudaEventRecord(start);
    // ... kernel launch ...
    cudaEventRecord(stop);
    cudaEventSynchronize(stop);
    float timeComp = 0;
    cudaEventElapsedTime(&timeComp, start, stop); // milliseconds
    ```
  </Accordion>
</AccordionGroup>
